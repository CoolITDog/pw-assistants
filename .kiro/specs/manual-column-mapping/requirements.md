# Requirements Document: Manual Column Mapping

## 1. 项目概述

### 1.1 项目背景
Excel Processor桌面应用目前要求导入文件的列名必须与系统预期的列名完全匹配才能进行数据处理。这在实际使用中限制了灵活性，因为用户可能从不同来源获得格式略有差异的文件。

### 1.2 问题陈述
用户导入Excel/CSV文件时，如果原始列名与系统预期的列名不匹配，无法自动处理数据。用户需要手动修改源文件列名或调整系统预期列名，这增加了使用门槛和操作复杂性。

### 1.3 解决方案概述
添加手动列名映射功能，当列名不匹配时弹出对话框让用户手动建立映射关系。用户可以将源文件的列（如"A"、"B"、"C"）映射到目标列名（如"距坝理财"、"测量值"等）。

## 2. 功能需求

### 2.1 列名匹配检查 (FR-001)
**需求编号**: FR-001  
**优先级**: 必须  
**描述**: 系统应在文件导入时自动检查源文件列名与系统预期列名的匹配情况。  
**详细说明**:
- 系统应读取源文件的表头信息
- 将源列名与预设的期望列名列表进行比较
- 计算匹配度分数（0-1）
- 识别完全匹配、模糊匹配和未匹配的列
- 标记必需列是否都有对应映射

**验收标准**:
- AC-001.1: 对于完全相同的列名，系统应识别为完全匹配
- AC-001.2: 对于相似但不完全相同的列名（如"距坝里程"和"距坝里程1"），系统应提供模糊匹配建议
- AC-001.3: 匹配度分数应在导入后立即显示给用户
- AC-001.4: 必需列缺失映射时应被明确标记

### 2.2 手动映射对话框 (FR-002)
**需求编号**: FR-002  
**优先级**: 必须  
**描述**: 当列名不匹配时，系统应弹出对话框让用户手动配置映射关系。  
**详细说明**:
- 对话框应并排显示源列名列表和目标列名列表
- 用户应能通过拖拽或下拉菜单建立映射关系
- 系统应提供自动匹配建议
- 必需列应用不同颜色或图标高亮显示
- 支持映射关系预览和验证

**验收标准**:
- AC-002.1: 对话框应在匹配度低于阈值时自动弹出
- AC-002.2: 用户应能通过拖拽源列到目标列建立映射
- AC-002.3: 每个源列最多只能映射到一个目标列
- AC-002.4: 所有必需列都必须有映射才能确认
- AC-002.5: 对话框应提供"取消"和"确认"按钮

### 2.3 自动匹配建议 (FR-003)
**需求编号**: FR-003  
**优先级**: 应该  
**描述**: 系统应提供智能的自动匹配建议，减少用户手动配置的工作量。  
**详细说明**:
- 基于字符串相似度算法（如编辑距离）提供建议
- 支持子字符串匹配（如"测量值_A"匹配"测量值"）
- 支持同义词映射（如"里程"匹配"距坝里程"）
- 每个建议应包含置信度分数
- 用户应能一键接受所有建议

**验收标准**:
- AC-003.1: 自动建议的准确率应达到80%以上
- AC-003.2: 每个建议应显示置信度百分比
- AC-003.3: 用户应能接受单个建议或全部建议
- AC-003.4: 系统应记录用户对建议的接受/拒绝，用于改进算法

### 2.4 映射模板管理 (FR-004)
**需求编号**: FR-004  
**优先级**: 应该  
**描述**: 系统应支持保存和加载列名映射模板，方便重复使用。  
**详细说明**:
- 用户应能保存成功的映射配置为模板
- 模板应按名称、描述和适用场景分类
- 系统应提供预设的系统模板
- 导入文件时自动推荐匹配的模板
- 支持模板的编辑、删除和共享

**验收标准**:
- AC-004.1: 用户应能保存当前映射配置为新模板
- AC-004.2: 系统应自动推荐匹配度最高的模板
- AC-004.3: 用户应能查看和管理所有模板
- AC-004.4: 模板应用后用户应能进一步调整

### 2.5 映射验证和错误处理 (FR-005)
**需求编号**: FR-005  
**优先级**: 必须  
**描述**: 系统应验证映射关系的完整性和正确性，并提供清晰的错误提示。  
**详细说明**:
- 验证必需列是否都有映射
- 检查映射冲突（同一源列映射到多个目标列）
- 验证目标列名不重复
- 提供具体的错误提示和修复建议
- 支持批量验证

**验收标准**:
- AC-005.1: 系统应在用户确认前自动验证映射
- AC-005.2: 验证错误应明确指示问题列和修复建议
- AC-005.3: 用户应能批量验证多个文件的映射配置
- AC-005.4: 验证结果应保存到日志供审计

### 2.6 向后兼容性 (FR-006)
**需求编号**: FR-006  
**优先级**: 必须  
**描述**: 新功能不应影响现有的严格匹配模式。  
**详细说明**:
- 现有用户配置应自动迁移到新格式
- 提供开关选项启用/禁用手动映射功能
- 保持原有API接口的兼容性
- 错误情况下回退到原有严格匹配模式

**验收标准**:
- AC-006.1: 升级后现有用户配置应保持不变
- AC-006.2: 用户应能在设置中启用手动映射功能
- AC-006.3: 手动映射失败时应优雅回退到严格匹配
- AC-006.4: 所有现有测试用例应继续通过

## 3. 非功能需求

### 3.1 性能需求 (NFR-001)
**需求编号**: NFR-001  
**类别**: 性能  
**描述**: 手动映射功能应具有可接受的性能表现。  
**详细要求**:
- 列名匹配检查应在100ms内完成（100列以内）
- 手动映射对话框应在200ms内打开
- 模板搜索应在50ms内完成（100个模板以内）
- 大数据文件（>10MB）处理不应阻塞UI

### 3.2 可用性需求 (NFR-002)
**需求编号**: NFR-002  
**类别**: 可用性  
**描述**: 手动映射功能应易于使用，学习曲线平缓。  
**详细要求**:
- 对话框布局直观，源列和目标列清晰区分
- 拖拽操作流畅，提供视觉反馈
- 错误提示明确，提供具体修复指导
- 支持键盘导航和快捷键操作
- 提供上下文帮助和工具提示

### 3.3 可靠性需求 (NFR-003)
**需求编号**: NFR-003  
**类别**: 可靠性  
**描述**: 手动映射功能应稳定可靠，数据不丢失。  
**详细要求**:
- 映射配置应自动保存，防止意外丢失
- 支持撤销/重做操作
- 错误情况下应有恢复机制
- 模板数据应定期备份
- 系统崩溃后应能恢复上次操作状态

### 3.4 安全性需求 (NFR-004)
**需求编号**: NFR-004  
**类别**: 安全性  
**描述**: 手动映射功能应符合安全最佳实践。  
**详细要求**:
- 列名输入应进行XSS防护
- 公式验证应沿用现有安全机制
- 模板数据存储在用户本地，不自动上传
- 操作应记录日志供审计
- 用户数据不应泄露给第三方

### 3.5 兼容性需求 (NFR-005)
**需求编号**: NFR-005  
**类别**: 兼容性  
**描述**: 手动映射功能应与现有系统和环境兼容。  
**详细要求**:
- 支持Windows 10/11操作系统
- 兼容现有Electron 31架构
- 支持React 18和TypeScript 5
- 与现有文件格式（.xlsx, .xls, .csv）完全兼容
- 不影响现有插件和扩展功能

## 5. 数据需求

### 5.1 映射配置格式 (DR-001)
**需求编号**: DR-001  
**描述**: 映射配置应采用标准化的数据结构。  
**详细要求**:
```typescript
interface ColumnMapping {
  id: string;
  sourceColumn: string;      // 源列名
  outputName: string;        // 目标列名
  mappingType: 'auto' | 'manual' | 'preset';
  confidence?: number;       // 自动匹配置信度
  isRequired: boolean;       // 是否为必需列
  createdAt: Date;           // 创建时间
  formula?: string;          // 计算列公式
  order: number;             // 输出顺序
}
```

### 5.2 模板存储格式 (DR-002)
**需求编号**: DR-002  
**描述**: 映射模板应采用持久化存储格式。  
**详细要求**:
- 模板存储在用户本地文件系统
- 使用JSON格式便于读写和维护
- 包含模板元数据（名称、描述、创建时间等）
- 支持版本控制，便于未来扩展
- 提供导入/导出功能

### 5.3 匹配配置格式 (DR-003)
**需求编号**: DR-003  
**描述**: 匹配算法配置应采用可配置的格式。  
**详细要求**:
- 支持配置模糊匹配阈值
- 可定义同义词映射关系
- 可配置忽略的字符集
- 支持不同文件类型的特定配置
- 配置应支持热更新

  // 现有接口保持不变

    sourceHeaders: string[], 
    templateId: string

**描述**: React组件应定义清晰的Props接口。
